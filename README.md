# ICPC reference

A landscape, three-column reference integrating the supplied team material with
KACTL. The full reference has a clickable section index on its first page and a
**Programming languages** section for the C++, Java and Python starter templates.
There is no separate cover. Both generated PDFs are limited to **25 pages**.

- [Full reference PDF](doc/reference.pdf)
- [Shared topics PDF, without language templates](doc/topics.pdf)
- [Full LaTeX source](doc/reference.tex) and [plain text](doc/reference.txt)
- [Topic LaTeX source](doc/topics.tex) and [plain text](doc/topics.txt)
- [Content and layout parameters](doc/reference.json)
- [Source coverage](doc/SOURCES.md) and [KACTL provenance](vendor/kactl/UPSTREAM.md)

## Organization

```text
cpp/template.cpp        C++ starter only
java/Main.java          Java starter only
python/template.py      Python starter only
topics/<subject>/       shared reusable examples, regardless of language
vendor/kactl/content/   pinned KACTL sources, grouped by subject
doc/                    catalogue, layout, generated LaTeX/text/PDFs
scripts/                renderer and validation
build/                  compiler and LaTeX intermediates (ignored)
```

The language directories each contain exactly one base template. Shared C++, Java
and Python material is grouped by topic under `topics/`, and appears in the same
subject sections as the corresponding KACTL material. See [topics/README.md](topics/README.md)
for the subject-to-source mapping. KACTL keeps its original folder structure so
its relative header dependencies continue to work.

The C++ starter retains the original helpers and adds KACTL's `rep`, `all`, `sz`,
`pii` and `vi` definitions plus an explicit `<cassert>` include. KACTL's duplicate
starter is omitted from the reference. All 135 other active default KACTL imports,
mathematical notes, diagrams and the algorithm checklist are included.

C++ quick references cover container calls and complexity, strings and parsing,
lambda captures, sorting and binary-search APIs. The modular arithmetic section
adds division/inverse conditions, exponent rules, linear congruences, CRT,
binomial coefficients and geometric sums, with helpers that take an explicit
modulus and use 128-bit intermediates for 64-bit arithmetic.
The opening C++ subsection also prints the compact Makefile in
`topics/programming_languages/`.

## Build and check

```sh
make              # generate, compile, validate, then publish both PDFs to doc/
make generate     # generate the two LaTeX/text references and KACTL manifest
make check        # compile/test the team templates and shared examples
make check-kactl  # compile 123 standalone KACTL headers with the C++ starter
make cpp          # compile cpp/template.cpp into build/sol
make clean        # remove intermediate LaTeX files, retaining published PDFs
```

The build needs Python 3.11+, a C++17 compiler (also used for KACTL checksums),
`latexmk`, `pdflatex`, Poppler's `pdfinfo`/`pdffonts`, and the LaTeX packages listed
in `doc/layout.tex`, including Inconsolata and adjustbox. Team snippet checks
also require a JDK. The vendored sources make subsequent builds offline; LaTeX
does not use shell escape.

The C++ checks run the API examples and compare modular helpers with exhaustive
small-modulus results and 64-bit boundary cases, with undefined-behavior checking.

Both PDF builds must pass the page-cap, landscape, font-embedding, reference and
overflow checks before the Makefile copies them into `doc/`. The first-page page
numbers and links are generated by LaTeX, so they update when content changes.
Build intermediates are isolated in `build/latex/` to avoid collisions with an
editor's LaTeX preview files.

`make check-kactl` honors upstream's seven exclusions for configurable fragments;
see [UPSTREAM.md](vendor/kactl/UPSTREAM.md). It verifies compilation, not algorithm
correctness across every possible input. The original supplied PDFs remain at
the repository root.

## Edit or extend

1. Edit the language starter or add reusable material under `topics/<subject>/`.
2. Register each team snippet's path, language, title and assumptions in
   `doc/reference.json`; place it in a shared subject section.
3. Run the relevant checks and `make`.

The renderer checks that all team snippets are registered exactly once and that
language folders contain only a template. KACTL's active imports come from its
`chapter.tex` files; `doc/kactl-manifest.json` records the included files and code
checksums. Author, source, license and dependency comments are retained in the
vendored files.

The current layout uses A4 landscape, three columns, 6 mm margins, 7 pt embedded
Inconsolata code and 7.4 pt body text. These dimensions and the maximum page count
are parameterized in `doc/reference.json`; styles are in `doc/layout.tex`. Print
at actual size. Generated `.tex` and `.txt` files should be rebuilt from the
catalogue and editable sources.
Blank code lines are suppressed only in the PDF, and the algorithm checklist
flows as grouped prose; source files and generated text retain the originals.
